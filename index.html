Setup guide — pick what fits your team
🔥 FIREBASE — recommended: real-time, free, nothing to host 1. console.firebase.google.com → Add project (any name, e.g. talabat-tools) → Create. 2. In the project: Build → Realtime Database → Create Database → pick a location → Start in test mode. 3. ⚙ Project settings → Your apps → Web (‹/›) → Register app → copy the firebaseConfig object. 4. Paste it on the left, keep one workspace name for everyone, Connect — done. Teammates get every change within about a second while the page is open. Note: test-mode rules stay open for 30 days; afterwards set Rules to {"rules":{".read": true,".write": true}} or enable Authentication → Anonymous and require auth. Keep the workspace name hard to guess if you want it private-ish. 🐙 GITHUB — no new accounts: the shared settings live as a JSON file inside a repo you control 1. Reading is zero-setup for public repos. 2. To publish edits once per editor: GitHub → Settings → Developer settings → Fine-grained personal access tokens → Generate new token → Repository access: only this repo → Permissions → Contents: Read and write → paste it above. 3. Readers/consumers need no token at all. Everyone sees changes within the poll interval (GitHub caches raw files a few minutes). 🔗 REST ENDPOINT — any JSON store with GET + PUT Create a bin on a JSON-storage service or point it at your own API / Cloudflare Worker, then paste the URL. Use “Copy team link” to hand the same endpoint to everyone.
